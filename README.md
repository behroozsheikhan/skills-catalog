# اسکیل کاتالوگ · Skill Catalog

کاتالوگ استاتیک فارسی برای Agent Skills، ساخته‌شده با **Astro** و آمادهٔ انتشار در **GitHub Pages**. داده‌ها و ابزارهای پایتون قبلی بدون تغییر در `skills-catalog/` نگهداری شده‌اند.

## اجرا

Node.js **22.12+** لازم است.

```bash
npm ci
npm run dev                       # http://localhost:4321/skills-catalog/
BASE_PATH=/ npm run dev           # پیش‌نمایش روی ریشهٔ دامنه
npm run check
npm test
npm run build
npm run preview
```

خروجی `dist/` شامل صفحات مستقل همهٔ **۷٬۷۶۴ اسکیل**، فهرست قابل مرور بدون JavaScript، صفحهٔ درباره، sitemap، robots.txt و ایندکس جستجو است. خروجی ساخت وارد Git نمی‌شود.

## امکانات

- طراحی RTL با وزیرمتنِ محلی؛ بدون سرویس فونت خارجی.
- تم روشن/تاریک با تبعیت اولیه از سیستم و ذخیرهٔ انتخاب کاربر.
- جستجوی سمت مرورگر در نام، منبع، توضیح و کاربرد فارسی/انگلیسی؛ مترادف‌های منتخب و نرمال‌سازی حروف فارسی.
- فیلتر ترکیبی موضوع، منبع، کاربرد و داشتن ترجمه؛ مرتب‌سازی، صفحه‌بندی و حفظ وضعیت در URL.
- فیلتر موبایل با focus trap و Escape؛ پشتیبانی از reduced motion، صفحه‌کلید و حالت بدون نتیجه/خطای شبکه.
- جزئیات کوتاه دوزبانه، لینک منبع و GitHub، تاریخ ثبت‌شده، وضعیت ترجمه و موارد مشابه؛ **بدون نمونهٔ درخواست**.
- HTML استاتیک برای SEO؛ canonical بدون query، meta اختصاصی، Open Graph، sitemap و صفحات فهرست قابل crawl.
- علاقه‌مندی‌ها روی کارت و جزئیات، با فیلتر «فقط علاقه‌مندی‌ها»، ذخیره در localStorage و همگام‌سازی تب‌های همان مرورگر. بدون ثبت‌نام؛ بین دستگاه‌ها همگام نمی‌شود و با پاک‌کردن داده‌های سایت حذف می‌شود. خطای ذخیره‌سازی به کاربر اعلام می‌شود.
- بدون بک‌اند، حساب کاربری یا analytics. ایندکس هنگام نزدیک‌شدن به نتایج یا تعامل بارگیری می‌شود؛ جدا از bundle اولیه (حدود ۷٫۹MB خام / ۱٫۴۲MiB gzip برای این نسخه). تعداد کارت‌های هر صفحه قابل انتخاب است: ۱۲ (پیش‌فرض)، ۲۴، ۴۸ یا ۹۶؛ انتخاب در URL حفظ می‌شود.

## وضعیت محتوا — مهم

**پوشش اولیهٔ فارسی: ۷٬۷۶۴ اسکیل؛ پوشش عددی به معنی کیفیت تأییدشده نیست.**

پس از بازخورد دربارهٔ ناخوانایی ترجمه‌های ماشینی، بازنویسی مستقیم از متن منبع برای مخاطب برنامه‌نویس انجام شد. هر ۷٬۲۶۹ متن یکتا (پوشش همهٔ ۷٬۷۶۴ اسکیل) بازنویسی شده است؛ متن معوقی در دادهٔ فعلی باقی نمانده است. در آخرین نوبت، ۱۲۹ متن یکتا با پوشش ۱۵۶ اسکیل تکمیل شد. رکوردهای این فرایند `method: editorial` و `editorialVersion: 1` دارند؛ ترجمه‌های قدیمیِ `machine` یا `assisted` بدون بازنویسی به این وضعیت ارتقا نیافته‌اند. این بازنویسی‌ها با Google Translate تولید نشده‌اند. پایان این مرحله به معنی تأیید انسانی یا تضمین بی‌خطابودن ترجمه‌ها نیست.

وضعیت زنده با `npm run translations` گزارش می‌شود. برای خروجیِ فقط متن‌های اصلیِ باقیمانده: `npm run translations -- --editorial-pending --export /tmp/editorial-pending.jsonl`. معیار نگارش در `data/TRANSLATION-GUIDE.md` آمده است.

گزارش دقیق پوشش در `data/translation-report.json` نگهداری می‌شود و با `npm run translations` نیز از روی دادهٔ فعلی محاسبه می‌شود. متن‌های یکسان فقط یک‌بار ترجمه و بر اساس تطابق کامل متن منبع بازاستفاده می‌شوند.

ترجمه‌ها در `data/fa.json` قرار دارند و همگی **پیش‌نویس (`draft`)** هستند؛ نه محتوای بازبینی‌شدهٔ انسانی. پوشش اولیه عمدتاً با Google Translate و محافظت از نام‌ها، اصطلاحات فنی و دستورهای نقل‌شده تولید شد؛ اکنون همهٔ متن‌های دادهٔ فعلی مستقیماً از منبع بازنویسی شده‌اند. اعتبارسنجی خودکار جای بازبینی انسانی را نمی‌گیرد. متن اصلی همیشه کنار متن فارسی باقی می‌ماند؛ بیشتر منابع انگلیسی‌اند و تعداد کمی چینی یا ترکیبی هستند.

- فیلدهای `what` و `use_when` خالی با حدس پر نمی‌شوند.
- اگر `what` خالی باشد، متن موجود `description` جداگانه ترجمه می‌شود؛ همان متنی که سایت پیش‌تر به انگلیسی نمایش می‌داد.
- نشانه‌های `…` و `...` حفظ می‌شوند؛ جای نشانه ممکن است متناسب با ترتیب واژه‌ها در فارسی تغییر کند، اما ادامه‌ای به متن اضافه نمی‌شود.
- عنوان فارسی اختصاصی فقط برای مواردی که قبلاً نوشته شده‌اند وجود دارد. سایر کارت‌ها نام اصلی و توضیح فارسی را نشان می‌دهند، نه عنوان حدسی.
- `sourceHash` از `what + '\n' + use_when` ساخته می‌شود؛ وقتی `what` خالی است، `\n + description` نیز در SHA-256 شرکت می‌کند. تغییر منبع، ترجمهٔ قدیمی را غیرفعال می‌کند.
- منبع ترجمه و روش تولید در رکوردهای خودکار ثبت شده‌اند. هیچ سرویس ترجمه‌ای هنگام بازدید از سایت یا build فراخوانی نمی‌شود.

```bash
npm run translations
npm run translations -- --export /tmp/pending-translations.jsonl
python3 tests/translation-pipeline.test.py
# عملیات اختیاری نگهداری، نیازمند اینترنت و ارسال متن‌های عمومی به Google Translate:
python3 scripts/bulk_translate.py --delay 2
# برای متن‌های پُراصطلاح که اعتبارسنجی درخواست عادی را رد کرده است:
python3 scripts/bulk_translate.py --delay 2 --fragmented
# ورود خروجی فقط پس از کنترل hash، فیلدهای خالی و اصطلاحات محافظت‌شده:
python3 scripts/import_translations.py translation-output/fa.json
```

اسکریپت ترجمه دارای cache قابل‌ادامه، محدودکنندهٔ نرخ درخواست و اعتبارسنجی placeholder است. خروجی ناقص یا حذف اصطلاحات، به ترجمهٔ معتبر تبدیل نمی‌شود. cache و خروجی‌های موقت در Git قرار نمی‌گیرند. محدودیت یا قطع سرویس ممکن است اجرا را متوقف کند؛ پیشرفت معتبر ذخیره می‌شود. workflow دستی `translate-catalog.yml` همین فرایند را اجرا و خروجی را به‌صورت artifact برای بررسی ارائه می‌کند؛ سایت به آن وابسته نیست.

برای افزودن یا اصلاح ترجمه، رکورد `author/name` را با `title`, `what`, `use_when`, `sourceHash`, `status` در `data/fa.json` قرار دهید. در صورت نیاز، `description` نیز جداگانه ذخیره می‌شود. نام‌ها و دستورهای نقل‌شده انگلیسی می‌مانند و متن ناقص تکمیل نمی‌شود.

موضوع‌ها از `topics.json` اولیه می‌آیند و ممکن است نادقیق باشند. کاربردها با قواعد شفاف در `src/lib/search.mjs` استخراج می‌شوند. جستجو مبتنی بر واژه‌نامه است، نه جستجوی معنایی هوشمند. پیشنهاد مشابه بر اساس موضوع/کاربرد/منبع است، نه رتبهٔ کیفیت. نشان منبع شناخته‌شده، تضمین اصالت یا امنیت نیست. لینک‌ها در این نسخه بررسی زنده نشده‌اند.

## انتشار در GitHub Pages

1. در **Settings → Pages → Build and deployment**، گزینهٔ **GitHub Actions** را انتخاب کنید.
2. تغییرات باید از طریق PR به `main` برسند؛ workflow فایل `.github/workflows/pages.yml` با push به `main` یا اجرای دستی شروع می‌شود.
3. workflow تست و بررسی type را اجرا می‌کند، سایت را می‌سازد و artifact را در Pages منتشر می‌کند.
4. `origin` و `base_path` از تنظیمات واقعی Pages دریافت می‌شوند؛ آدرس پیش‌فرض محلی `https://behroozsheikhan.github.io/skills-catalog/` است.

برای ساخت روی دامنهٔ اختصاصی/ریشه:

```bash
SITE_URL=https://example.com BASE_PATH=/ npm run build
```

انتشار زنده در این پیاده‌سازی انجام نشده؛ فقط workflow آماده شده است. `robots.txt` در پروژه‌پیج زیر `/skills-catalog/` قرار می‌گیرد؛ robots دامنهٔ اصلی را فقط مالک user-site کنترل می‌کند. sitemap را می‌توان مستقیم به Search Console معرفی کرد.

## ساختار

```text
src/lib/catalog.mjs       خواندن داده، تطبیق ترجمه و پیشنهاد مشابه
src/lib/search.mjs        نرمال‌سازی، مترادف‌ها و فیلترها
src/scripts/catalog.ts    تعامل مرورگر و URL
src/pages/                صفحات استاتیک و خروجی‌های sitemap/index
src/styles/global.css    طراحی واکنش‌گرا و دو تم
src/components/          کارت و آیکون‌ها
src/layouts/             پوسته و متادیتا
scripts/translations.mjs  گزارش پوشش و خروجی ترجمه‌های معوق
skills-catalog/           داده‌ها و ابزارهای اصلی (دست‌نخورده)
```

## آزمون مرورگر

```bash
npx playwright install --with-deps chromium
# در ترمینال دیگر:
BASE_PATH=/ npm run dev
npm run test:browser
```

برای سرور یا مرورگر موجود، `TEST_URL` (با اسلش پایانی) و `CHROMIUM_PATH` را تنظیم کنید. آزمون شامل جستجو، ترکیب فیلترها، URL، تم، صفحه‌بندی، جزئیات دوزبانه، موبایل ۳۲۰/۳۹۰px، حالت بدون JavaScript و خطا/تلاش مجدد شبکه است.
